| 신고·차단이 지나치게 강조됨 | ••• 안의 ‘안전 · 신고와 차단’ 보조 항목으로 접음. 서버 보호와 문의·운영 기능은 유지 |
| 최종 저장 지연·중복 우려 | 새로 선택한 사진의 Photos 식별자는 기기에만 보관. iPhone에서 접근 가능한 기존 사진의 파일 크기·SHA-256이 업로드 원본과 같을 때 기존 사진을 앨범에 연결. 서버 재다운로드·새 Photos 생성 생략. 편집·삭제·제한 권한·iCloud 등으로 확인 불가하면 기존 검증된 원본 저장 경로 사용 |

| 확정 후 로그·추가 선정 | 최종 사진에서 ‘전체 후보 · 친구 선택 기록 보기’로 모든 후보·친구별 최신 분류·제출 시각 조회. 사진 확대 시 사람별 반응 표시. 요청자는 추가로 모을 사진을 기기에 기록하고 같은 원본 앨범에 저장. 최초 확정·친구 제출·30일 만료는 변경하지 않음 |
| 100장 중 20장 선택 | 앱·SQL·안전 검사 상한 100장. 좋아/글쎄/별로/미분류의 가상화된 3열 목록, 친구별 보기, 그룹 전체 선택/해제. 선택을 친구 보기 사이에 유지. 이미 모은 사진은 추가 선정에서 제외 |

## 원본 저장 방식과 한계

원본을 서버에 올리지 않는 전면 개편은 적용하지 않았다. 기존 요청과 복구 경로를 보호하기 위해 원본 업로드·해시 검증·서버 원본 보관을 유지한다. 이번에는 **검증된 기존 사진 재사용**과 중복 조회·해시 처리부터 개선했다. 따라서 원본 업로드량이나 선택기 자체의 iCloud 다운로드 시간이 모두 없어지지는 않는다.

기존 사진 ID만으로 동일 원본이라고 판단하지 않는다. 저장 시 파일 크기·해시가 일치해야 재사용하며, 없거나 달라졌으면 보관한 원본으로 저장본을 만든다. 예전 요청처럼 기기 매핑이 없는 사진도 기존 저장 기능을 쓸 수 있다. iCloud 사진은 이번 경로에서 원본을 강제로 내려받지 않으므로 보관본 다운로드로 넘어갈 수 있다. 앨범 표시 순서는 Photos 설정에 따라 달라진다.

추가 선정은 **이 기기에 추가로 모으는 기록**이다. 친구에게 공유되는 서버 최종 선택을 수정하거나 사진 보관을 연장하지 않는다. 앱·기기 데이터 삭제 후 복구를 보장하지 않는다. 사진 앱에 저장한 원본은 앱·서버 삭제로 지워지지 않는다. 과거 수정 전 선택을 모두 보존한 이벤트 로그는 제공하지 않는다.

## 서버 연결 시 적용 범위

- `supabase/migrations/20261104162122_iphone_feedback.sql`: 100장 등록·공유 제한. 요청 행 잠금, 소유권·참여·확정 잠금·안전 검사 승인 대조는 유지.
- `supabase/functions/_shared/handler.ts`, `workflows.ts`: 100장 검사, 서버가 고른 비공개 미리보기 URL 배치 서명. 5장 단위 안전 검사는 유지하며 오류 시 공유하지 않는다.
- 원격 migration과 `app-actions` 함수를 함께 배포해야 서버 모드에서 100장이 동작한다. 실제 서버·키가 확인되지 않은 상태에서 임의 배포하지 않았다. 로컬 Expo Go 테스트에는 원격 배포가 필요 없다.
- 신규 라이브러리 설치·원본 일괄 삭제·main 병합·App Store/TestFlight 배포 없음.

## 검증과 iPhone 재테스트

자동 검사와 번들 생성 결과는 [출시 기록](app-store-release.md)에 구분해서 적는다. 합성 사진 100장을 넣은 실제 웹 번들에서 390px 화면·그룹 20장 선택·친구 보기 변경 시 선택 유지·확정·전체 후보 반응 조회·추가 선정·재실행 흐름을 확인했다. 이 테스트를 실제 사진 업로드 속도나 iPhone Photos 검증으로 보지는 않는다.

기존 Metro를 종료한 뒤 `mobile`에서 `npx expo start --go --clear`로 열어 재테스트한다. 계정 가입·Apple 결제가 필요한 단계는 아니다. 예전 사진도 남아 있는지 먼저 확인한다.

1. 같은 사진 10장/30장과 100장을 골라 준비 시간을 따로 기록한다. 로컬/서버, 기기·사진 용량·Wi-Fi·iCloud 여부를 함께 적는다.
2. 친구로 열어 오른쪽 다음·왼쪽 이전·이전/다음 버튼을 시험한다. 분류 저장 중 이동, 돌아가 수정, 수정 후 재제출까지 확인한다.
3. 요청자로 돌아와 좋아 20장 전체 선택, 친구 보기 전환, 해제·다시 선택, 최종 확정을 시험한다.
4. 전체 후보 기록에서 최종 사진이 아닌 사진의 친구별 반응과 제출 기록을 확인한다. 1장 추가로 모으고 앱을 다시 열어 기록을 확인한다.
5. 사진 접근을 전체·제한·거절로 나눠 시험한다. 같은 원본이 있으면 카메라롤 수가 늘지 않는지, 같은 앨범에 두 번 저장해도 중복되지 않는지 확인한다.
6. 원본 편집·삭제·기기 매핑 없는 예전 요청·iCloud 사진에서는 보관본 저장과 실패 안내·재시도가 일치하는지 확인한다. 100장 처리 중 강제 종료·네트워크 단절도 포함한다.
7. 서버 모드에서는 실제 안전 검사·서명 URL·권한·동시 100장 초과 차단·삭제·30일 만료를 별도 검증한다. 로컬 PostgreSQL 엔진은 실제 Storage/Auth/네트워크 검증을 대체하지 않는다.

화면 확인 자료: [390px 분류별 전체 선택](screenshots/feedback-groups-20261105.png). 합성 사진을 사용한 웹 화면이며 iPhone 사진첩 검증 자료는 아니다.

성능 개선율·저장 완료 시간은 아직 실측하지 않았다. 실제 기기 검증 전 출시 완료로 판단하지 않는다.

# 홈·친구·보관함과 이벤트 메인 업데이트

2026-11-05 · 개발·재테스트 안내용 · `codex/shared-event-experiment`

## 화면과 상태

- 하단은 홈/친구/보관함 세 탭이다. 기존 소개 화면의 제목과 설명을 홈에서 사용하며 최초 닉네임·동의 입력은 유지한다. 설정은 홈에서 연다.
- 홈에는 진행 중 이벤트만 표시한다. 내 업로드만 있으면 ‘보낸 요청’, 다른 사람의 업로드만 있으면 ‘받은 요청’, 양쪽이 업로드하면 ‘함께한 이벤트’다. 사진 가져오기만으로 업로드 여부를 바꾸지 않는다.
- 모든 업로드 묶음이 최종 확정되면 완료로 처리한다. 아직 업로드 중인 빈 묶음이 있으면 완료하지 않는다. 이벤트를 만든 사람은 하단에서 수동 마감할 수 있다. 완료·마감은 홈에서 빠지고 보관함에 나타난다.
- 서버는 일부 사진 묶음이 안전 검사 때문에 보이지 않는 경우에도 전체 이벤트의 완료 상태를 계산한다. 보이는 사진만으로 임의 완료 처리하지 않는다. 마감 후 새 업로드·투표·새 참여를 막고 기록 조회와 데이터 삭제는 유지한다.

## 이벤트 메인과 선택

사람별 사진 섹션 안에 좋아/글쎄/별로/친구 투표 전 묶음을 표시한다. 제출 전의 현재 반응도 바로 반영한다. 여러 친구의 반응이 섞이면 좋아→글쎄→별로 순으로 묶고 사진별 세 투표 수를 함께 표시해 다른 의견을 숨기지 않는다. 기존 본인 투표 기록은 친구 집계에서 제외한다. 글쎄는 약하게, 별로는 더 낮은 불투명도로 표시하되 글자와 개수도 함께 읽을 수 있다.

이벤트 이름 수정과 함께할 사람 초대는 사진 목록의 하단으로 옮겼다. 화면 맨 아래의 고정 행동은 다음과 같다.

| 상태 | 왼쪽 | 오른쪽 |
|---|---|---|
| 내 사진 업로드 전 | 사진 추가(전체 폭) | 없음 |
| 내 사진 업로드 후 | 사진 추가(절반) | 최종 선택(절반) |
| 완료·마감 후 | 사진 추가 없음 | 선택 결과 |

본인 업로드에는 투표 버튼을 제공하지 않으며 앱 도메인과 서버 RPC도 본인 투표·제출을 거절한다. 친구 투표를 본 뒤 업로더가 최종 선택한다. 여러 번 나눠 올렸으면 최종 선택 버튼에서 업로드 묶음을 골라 확정한다. 기존 분류·제출·원본 저장 기록과 사진 확대·가져오기는 보존한다.

## 저장된 친구와 초대

링크로 같은 이벤트에 연결된 참여자의 사용자 ID·닉네임을 친구 프로필로 저장한다. 이벤트나 사진이 없어져도 다음 초대에 사용할 수 있도록 남긴다. 기기의 연락처를 읽지는 않는다. 차단되거나 삭제·이용 제한 중인 계정은 친구 목록과 초대에서 제외한다.

친구 탭 또는 이벤트 하단에서 저장된 친구에게 초대를 보낼 수 있다. 초대는 곧바로 강제 참여시키지 않으며 친구 탭의 받은 초대에서 수락/거절한다. 받는 사람만 응답할 수 있고, 수락 시 정원(3명)·차단·안전 검사·마감 상태를 다시 확인한다. 동일한 대기 초대를 중복 생성하지 않는다. 마감·완료 시 대기 초대도 종료한다. 서버 연결에서는 공개할 사진의 안전 검사를 먼저 마쳐야 한다.

## 변경과 검증 범위

로컬 lint·TypeScript·앱 테스트 55개·SQL/RLS 테스트 15개·웹 production export가 통과했다.

`20261105103115_event_navigation_and_friends.sql`은 생성자·완료/마감 시각, 친구 프로필, 앱 내 초대와 RLS·권한 검사를 추가한다. 기존 migration을 수정하거나 원격 DB에 적용하지 않았다. 로컬 모드에도 프로필·초대·마감을 저장하며 재실행 시 복원한다.

앱 테스트는 업로드에 따른 이벤트 이름 분류, 완료 상태, 본인 투표 차단, 친구 반응 집계, 참여자별 하단 버튼 노출, 프로필 보존과 재초대·수락·마감 후 거절을 확인한다. 화면 조건 테스트는 실제 컴포넌트 코드를 실행하되 네이티브 뷰와 저장 매체를 대체한다. SQL 테스트는 PGlite에서 migration·RLS·초대 정원 재검사·마감 차단·프로필 보존을 실행한다.

브라우저 창 제어 승인 시간이 초과되어 실제 렌더 화면의 시각 검증은 수행하지 못했다. 모의 화면 테스트나 웹 export를 실기기 확인으로 간주하지 않는다. 실제 Supabase Auth/Storage·두 기기 동기화·iPhone 안전 영역과 큰 글자는 추가 검증 대상이다.

## Expo Go 재테스트

1. 새 QR로 실행하고 홈/친구/보관함 탭이 표시되는지 확인한다. 홈에서 사진을 올려 새 이벤트를 만든다.
2. 본인 시점에 ‘보낸 요청’과 사진 추가/최종 선택이 보이고, 사진 상세에는 본인 투표 버튼이 없는지 확인한다.
3. ‘테스트 친구로 이벤트 보기’로 전환한다. 사진 업로드 전에는 ‘받은 요청’과 사진 추가 버튼만 있어야 한다.
4. 친구 시점에서 사진을 올린다. ‘함께한 이벤트’가 되고 사진 추가 옆에 최종 선택이 생겨야 한다.
5. 서로의 사진에 투표한다. 결과 화면에 들어가지 않아도 이벤트 메인에서 반응별 묶음과 개수가 바뀌는지 확인한다.
6. 양쪽 사진의 최종 선택을 마치거나 생성자 시점에서 마감한다. 홈에서 빠지고 보관함에서 다시 볼 수 있어야 한다.
7. 연결된 친구 프로필이 남는지 확인한다. 다음 이벤트에 저장된 친구를 초대하고 받은 초대를 수락한다. 실제 두 기기 초대는 서버 적용 후 검증한다.

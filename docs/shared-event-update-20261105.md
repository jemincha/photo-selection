# 공유 이벤트와 사람별 사진 섹션

2026-11-05 · 개발·재테스트 안내용

## 이번 변경

홈의 보낸/받은 셀렉 구분을 없애고 공유 이벤트를 보여준다. 사진 선택 후 자동으로 이벤트와 첫 사진 묶음을 만들고 기존 업로드 처리·복원·실패 재시도를 사용한다. 이벤트 이름은 ‘함께한 순간’으로 시작하며 이벤트 안에서 ‘제주 여행’, ‘주말 데이트’처럼 바꿀 수 있다. 참여자는 기존 정원인 최대 3명을 유지한다.

이벤트 안에는 각 참여자의 사진 섹션이 있다. 사진을 추가로 올리면 같은 이벤트 안의 업로더 섹션에 합쳐 표시한다. 업로드하지 않은 참여자도 빈 섹션을 가진다. 각 사진을 누르면 확대해서 보고, 타인의 사진에 ‘내 섹션으로 가져오기’를 사용할 수 있다.

A가 찍어 올린 B의 사진을 B가 가져오면 A 섹션에 원본이 남고 B 섹션에도 같은 사진이 표시된다. 파일 복사·재업로드·업로더 변경은 없다. 같은 사진을 다시 가져와도 한 번만 표시한다. ‘내 섹션에서 빼기’는 가져오기 기록만 지우며 A의 원본은 삭제하지 않는다. 원본이 삭제·만료되거나 접근할 수 없게 되면 가져온 사진도 보이지 않는다.

가져오기는 사진을 모아 보는 기능이다. 기존 분류·제출·최종 확정은 원래 업로드 묶음을 기준으로 유지하며, 가져온 사람에게 원본 다운로드나 원본 삭제 권한을 주지 않는다. 이번에는 그 선택·저장 권한 구조까지 바꾸지 않는다.

## 기존 기록과 공유

이전 데이터와 URL은 유지한다. 기존 단독 셀렉도 이벤트 목록에서 열 수 있지만, 과거 단독 공유 약속과 사진 고정은 유지하므로 그 이벤트에 새 업로드 묶음을 추가하지 않는다. 새로 함께 사진을 모으는 작업은 새 이벤트에서 시작한다.

서버에서는 업로드한 사람만 안전 검사 전 사진을 볼 수 있다. 이벤트의 ‘새 사진 공개하기’ 또는 초대 영역에서 동의·안전 검사를 마치면 다른 참여자에게 공개된다. 초대받은 사람은 개별 사진 분류 화면 대신 이벤트로 들어온다. 신고·차단·삭제·초대 폐기 기능은 유지한다.

기존 `albums`와 `requests`를 재사용하며, `album_photo_sections`에는 이벤트·참여자·사진 참조만 저장한다. RLS로 본인 섹션만 추가/제거할 수 있고, 같은 이벤트에서 볼 권한이 있는 사진만 가져온다. 사진 또는 참여자 삭제 시 참조도 FK cascade로 정리한다.

서버에는 `supabase/migrations/20261105085759_shared_event_sections.sql` 적용이 필요하다. 기존 CLI로 파일을 생성했으며 원격 배포는 하지 않았다. 서버 검증은 로컬 PostgreSQL 엔진(PGlite)의 실제 SQL/RLS 실행이며 실제 Supabase Auth·Storage 검증을 뜻하지 않는다.

## Expo Go에서 확인할 순서

로컬 검증: 앱 테스트 52개와 SQL/RLS 테스트 11개 통과. lint·TypeScript·웹 production export를 확인했다. 앱 저장소 검사는 실제 로컬 repository 함수를 실행하고 저장 매체·Expo 모듈만 대체해 재시작 복원·실패 시 롤백·원본 삭제 후 참조 정리를 검사한다.

1. 기존 실행 안내대로 서버를 실행하고 새 QR로 앱을 연다. 홈에서 ‘사진 올려 이벤트 만들기’를 누르고 테스트 사진 3~5장을 선택한다.
2. 업로드 후 ‘이벤트에서 사진 보기’를 누른다. ‘이벤트 이름’에서 여행·데이트 이름으로 바꾸고 내 사진 섹션을 확인한다.
3. 로컬 모드에서는 하단의 ‘테스트 친구로 이벤트 보기’를 누른다. 테스트 친구의 빈 섹션이 나타난다.
4. 첫 사용자의 사진을 열고 ‘내 섹션으로 가져오기’를 누른다. 두 사람의 섹션에 같은 사진이 보이며 가져온 사진에 출처가 표시된다.
5. 같은 사진을 다시 열어 ‘내 섹션에서 빼기’를 누른다. 원래 업로더 섹션에는 사진이 남아 있어야 한다.
6. 테스트 친구로 ‘이 이벤트에 사진 추가’를 눌러 사진을 올린다. 같은 이벤트의 테스트 친구 섹션에 들어가는지 확인한다.
7. 다시 가져오고 앱을 재실행한다. 이벤트 이름과 가져온 기록이 유지되는지 확인한다. 서로 다른 이벤트에는 사진이 섞이지 않아야 한다.

실제 iPhone 화면·두 기기 동기화·사진 권한·메모리 측정은 별도 검증 대상이다. 이번 변경은 서버 배포나 스토어 제출을 포함하지 않는다.

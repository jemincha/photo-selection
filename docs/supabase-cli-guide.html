서버 변경을 파일로 남기는 도구

Supabase CLI · 설렉 v2 맞춤 안내

2026-10-22 · 실제 확인 버전 2.121.0 · 로컬 파일 생성까지 확인

서버 미연결 · 원격 변경 없음

1. 한눈에 이해하기

공유 후 사진을 바꾸지 못하게 하거나, 새 요청을 다른 앨범과 격리하는 서버 변경을 기록하고 검증할 때 사용합니다.

화면 색상이나 문구만 바꾸는 작업에는 필요하지 않습니다.

2. 실제 설치 범위

공식 npm supabase 2.121.0을 npm exec 캐시로 내려받아 Windows의 Node/npm에서 실행했습니다. 전역 설치나 앱 의존성 추가는 하지 않았습니다.

프로젝트에는 SQL과 무시되는 supabase/.temp/ 상태만 생성됐습니다. 기존 스킬·MCP와 CLI는 별개입니다.

Docker·로컬 DB·원격 프로젝트·키는 설정하지 않았습니다. 캐시 위치는 npm이 관리합니다.

3. 작동 구조

  1. 요구 확인
  2. 기존 SQL 검토
  3. CLI로 파일 생성
  4. SQL 작성
  5. 테스트 DB 검증
  6. 검토 후 적용
파일 생성과 서버 적용은 어떻게 다른가요?

이번에 확인: 버전 출력, migration 파일 생성. 이 단계에서는 서버 데이터가 바뀌지 않습니다.

아직 안 한 일: DB 연결, SQL 실행, 권한·동시성 검증. 파일이 있다고 서버가 안전하게 동작하는 것은 아닙니다.

4. 바로 쓰는 방법

저장소 루트의 PowerShell에서 버전과 도움말을 확인합니다.

npm.cmd exec --yes --package=supabase@2.121.0 -- supabase --version
npm.cmd exec --yes --package=supabase@2.121.0 -- supabase migration new --help
설렉 저장소의 Supabase CLI 2.121.0과 기존 migration을 확인해줘. 원격 연결이나 DB 변경은 하지 말고 파일 순서와 추가 SQL의 권한 검증 항목만 정리해줘.
이어서 작업할 때 복사할 요청문
docs/app-store-release.md를 기준으로 simple_v2 migration의 테스트 DB 검증을 이어가줘. 계정·서버가 준비됐는지 먼저 확인하고 기존 데이터를 보존해줘.

5. 내 프로젝트에 적용

실제 확인한 프로젝트는 설렉 하나입니다. 기존 앨범 단위 멤버십 위에 새 요청의 독립 공간과 공유 후 사진 고정을 추가합니다.

첫 과제는 20261022110646_simple_v2.sql 검토입니다. 기존 공동 앨범 호환, 새 요청의 비멤버 접근 차단과 사진 고정이 성공 기준입니다.

앱은 Expo가, SQL 변경 이력은 CLI가 담당합니다. 기획·개인정보 문서도 실제 서버 동작에 맞춰 갱신합니다. 기존 문서·테스트가 진도의 기준입니다.

6. 기대효과와 한계

검증: 버전 출력과 파일 생성 성공.

문서화된 기능: 로컬 개발, migration, DB 테스트 도구.

다음 제안: 서버 준비 뒤 권한 회귀 검증에 활용.

성능·절감률은 측정하지 않았습니다. 최초 실행/업데이트에는 다운로드가 필요할 수 있습니다. 로컬 DB에는 별도 Docker 환경이 필요하며 CLI 실행 자체가 서버 생성이나 과금 동의는 아닙니다.

7. 작은 시험 과제

SQL 세 파일의 순서를 확인하고 공개 RPC의 실행 권한과 멤버십 검사를 검토합니다. 새 파일을 만들거나 적용할 필요는 없습니다.

완료 기준: 검토 결과와 미실행 항목을 출시 기록에 남깁니다.

도구 설치 확인과 실제 제품 효과 검증을 구분합니다.

8. 관리·복구·출처

명령을 중지하면 이번 작업은 끝납니다. 전역 서비스·시작 프로그램은 설치하지 않았습니다. 사용하지 않으려면 npm exec를 호출하지 않으면 됩니다.

업데이트는 버전을 명시하고 테스트 환경에서 재검증합니다. 캐시를 지울 때는 해당 패키지만 확인하며, 프로젝트 SQL·전체 npm 캐시를 무턱대고 지우지 않습니다. 키·환경 파일은 커밋하지 않습니다.

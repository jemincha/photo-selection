# 사진 셀렉 앱 기획 v0.4 — 와이어프레임 기준

## 합의된 제품 방향

- 목표: 사진 셀렉 요청과 결과 전달의 마찰을 줄이고, 실제 iOS 앱 출시까지 경험한다.
- 이벤트 하나는 한 명의 게시자가 친구에게 자신의 사진 셀렉을 요청하는 공간이다.
- 같은 앱에서 요청자와 친구의 기능을 모두 지원한다. 역할은 이벤트마다 달라진다.
- 이벤트는 MVP에서 개인별 셀렉 요청을 뜻한다. 한 사용자가 같은 여행의 자신의 요청을 만들고 친구 요청에도 동시에 참여할 수 있다. 홈에서 요청을 열면 요청 소유자에 따라 역할이 자동으로 정해진다. 좋아요·의견·확정 상태는 요청마다 분리한다. 여행 전체를 묶는 상위 공간은 후속 확장이다.
- 친구는 좋아요로 사진을 고르고, 조합과 순서에 대한 의견은 텍스트로 전달한다.
- 자동 조합 추천, 조합 투표, 구조화된 조합 제안·순서 편집은 초기 MVP에서 제외한다.
- 요청자는 최종 사진을 선택·확정하고 원본을 저장한다.
- 미설치 친구를 위한 최소 웹 참여 경로는 같은 프로젝트에서 제공한다.
- 진행 순서: 기획 확정 → 클릭형 와이어프레임 → 기술 검증 → MVP 개발 → 파일럿·배포.

## 핵심 흐름

요청자: 로그인 → 이벤트 생성 → 사진 업로드 → 초대 공유 → 친구 반응 확인 → 최종 사진 선택·확정 → 원본 저장.

친구: 초대 링크 → 앱 또는 웹 진입 → 참여 → 사진 확인 → 좋아요·텍스트 의견 → 확정 결과 확인.

웹에서는 앱 설치를 강요하지 않는다. 앱 설치자는 같은 이벤트의 앱 화면으로 진입한다.

## MVP 권한

| 기능 | 요청자 | 친구 |
|---|---|---|
| 사진 보기·좋아요·의견 | 가능 | 가능 |
| 이벤트 생성·사진 업로드 | 가능 | 해당 이벤트에서는 불가 |
| 초대 관리 | 가능 | 불가 |
| 최종 사진 선택·확정 | 가능 | 불가 |
| 확정 결과 확인 | 가능 | 가능 |
| 원본 저장 | 가능 | 초기에는 제외 제안 |

## 와이어프레임 화면

| ID | 화면 | 주요 내용 |
|---|---|---|
| S0 | 소개·로그인 | 요청자 로그인, 초대받은 사용자의 참여 진입 |
| S1 | 홈 | 내가 요청한 이벤트·참여한 이벤트, 진행 상태 |
| S2 | 이벤트 생성 | 제목, 선택적 날짜 |
| S3 | 초대 공유 | 링크 복사·공유, 참여자 현황 |
| S4 | 업로드 | 다중 선택, 진행·실패·재시도 |
| S5 | 이벤트·사진 그리드 | 사진, 좋아요, 참여자, 이벤트 의견, 역할별 행동 버튼 |
| S6 | 사진 상세 | 좌우 스와이프로 이전·다음 탐색, 별로·글쎄·좋아 버튼, 사진별 의견, 선택 취소·되돌리기 |
| S7 | 최종 선택 | 요청자가 사진 선택, 친구 의견 참고, 확정 전 확인 |
| S8 | 확정 결과 | 선택된 사진, 요청자의 원본 저장, 저장 진행·실패·재시도 |
| W1 | 웹 초대 진입 | 이벤트 소개, 닉네임 참여, 앱 열기 선택 |

웹 참여자는 W1 이후 S5·S6·S8의 제한된 웹 화면을 사용한다. 별도의 전체 웹앱을 설계하지 않는다.

화면마다 필요한 기본·빈 상태·로딩·오류·권한 거부 상태를 설계한다. 요청자·친구 화면 차이와 이동 대상 ID를 표시한다.

형식 제안: 한국어 HTML/CSS 클릭형 와이어프레임. 390×844 모바일 화면, 사진은 X 표시 자리표시자, 화면별 파일과 전체 목차를 제공한다.

## 기술 방향 — 추천, 착수 전 확정

- Windows + VS Code에서 TypeScript로 개발.
- Expo + React Native + Expo Router, 웹 참여는 React Native Web 활용.
- Supabase Auth·Postgres·비공개 Storage, 이벤트 멤버십 기반 RLS.
- iPhone 12 실기기 검증, EAS development build·Build·Submit으로 iOS 테스트·배포.
- 웹 호스팅은 EAS Hosting 우선 검토. 실제 도메인·요금·서비스 등록은 미확정.
- 초기에는 별도 REST 서버·별도 웹 프로젝트·복잡한 모노레포를 만들지 않는다.

## 기술 검증 완료 기준

- JPEG·HEIC·iCloud 사진 선택 시 포맷·해상도·변환 여부 확인.
- 업로드된 파일과 다운로드 파일의 동일성 확인. 기기 원본과 선택 결과의 동일성은 별도로 확인.
- 썸네일과 원본 경로 분리, 저장에는 원본만 사용.
- 사진첩 저장 성공·권한 거부·부분 실패·재시도 동작 확인.
- 다른 이벤트의 사진·의견에 접근할 수 없도록 권한 검증.
- 앱 설치·미설치 초대 경로를 각각 확인.
- 사진첩 및 외부 앱의 표시 순서를 보장하지 않는다. 초기 MVP는 게시 순서를 구조화해 전달하지 않는다.

## 운영 규칙

1. 참여: 친구는 닉네임과 익명 세션으로 참여. 요청자는 계정 사용.
2. 의견: 사진별 의견과 이벤트 전체 의견을 제공. 후자는 조합·순서 의견 전달용.
3. 진행: 셀렉 중 / 확정됨 두 상태. 최종 확정 후 좋아요·의견은 읽기 전용.
4. 수정: 확정 전 요청자가 사진을 추가할 수 있음. 확정 후 수정은 MVP에서 제외.
5. 저장: 친구의 원본 다운로드는 초기에는 제외.
6. 보관: 원본 보관 기간·만료 안내·삭제 방식은 실제 데이터 업로드 전에 확정.
7. 파일 범위·사진 수·용량 상한은 기술 검증 결과와 비용을 바탕으로 확정.
8. 계정 삭제·이벤트 삭제·지원·개인정보 안내는 배포 준비에 포함.

1~3번은 사용자 확인으로 확정되었다. 4~5번은 와이어프레임의 범위 가정이며, 개발 전 확인한다.

## 범위 밖

자동 추천·유사도 분석·조합 투표·구조화된 순서 편집·갤러리 일괄 삭제·인스타 자동 게시·친구 사진 업로드·4인 이상 전용 최적화.

## 상세 화면 셀렉 UX — 이번 검토 시안

- 상세 화면은 사진 한 장씩 표시한다. 왼쪽 스와이프는 다음 사진, 오른쪽은 이전 사진으로 이동한다. 첫·마지막 사진에서는 순환하지 않는다. 세로 스크롤은 현재 사진의 의견 등 내용만 탐색한다.
- 스와이프는 분류를 바꾸지 않는다. 짧은 이동·세로 이동·취소된 제스처는 사진 이동도 수행하지 않는다.
- 별로는 사진 삭제·전체 제외·최종 확정이 아니라 개인의 의견이다. 요청자는 최종 선택에서 모든 사진을 볼 수 있다.
- 분류는 하단 별로 / 글쎄 / 좋아 버튼으로만 수행한다. 글쎄는 의도적인 애매 평가이며 아직 안 고름과 구분한다. 세 분류는 상호 배타적이다. 좋아는 기존 좋아요와 동일한 반응이다.
- 사진 영역의 좌우 방향키로도 탐색할 수 있다. 분류 버튼은 키보드로도 조작할 수 있으며 선택 취소와 직전 분류 되돌리기를 제공한다.
- 분류 후 현재 사진을 유지한다. 다음 사진은 사용자가 스와이프로 넘긴다.
- 확정 후 분류 버튼·의견 수정·되돌리기는 차단하지만 사진 스와이프 탐색은 허용한다.
- 사진 확대·축소와 앱 가장자리 뒤로 가기 제스처의 충돌은 iPhone 실기기 검증에서 확인한다.
- 상세 시안은 썸네일로 구조만 확인한다. 비슷한 사진 구별에 필요한 상세 이미지 해상도는 실제 구현에서 검증한다.

## 2026-10-09 구현 변경 — 아래 정책이 기존 요청 단위 홈/상세 정책보다 우선

- 첫 진입: 닉네임만 설정. 이후 홈은 그동안 참여한 앨범의 사진 표지·참여자·요청 수·진행/확정 상태를 보여주는 앨범 목록이다.
- 앨범은 여행/이벤트를 나타내며 여러 사람의 요청을 담는다. 참여자는 같은 앨범에 자신의 요청을 만들고 타인의 요청도 셀렉한다. 별도 역할 모드를 선택하지 않고 요청 소유자 ID로 권한을 판단한다.
- 현재 최대 참여자 3명 정책은 앨범 단위로 적용. 요청 초대로 앨범에 가입하면 기존/미래 요청 모두 접근한다. 앨범에 초대된 사용자가 확정 요청을 포함한 앨범 이력을 볼 수 있다는 점을 초대 화면에 안내한다.
- 상세: 좌우 스와이프로 사진 탐색. 별로/글쎄/좋아 버튼 저장 성공 후 다음 사진으로 자동 이동. 마지막 사진에서는 멈춘다. 이전 사진으로 돌아가 다른 버튼을 누르면 덮어쓴다. 선택 취소/되돌리기/이전·다음 버튼은 제거한다.
- 모든 사진을 분류한 뒤 제출 가능. 텍스트 의견은 선택사항이며 기본으로 접힌다. 제출 후 좋아로 고른 조합을 표시하고 종료한다. 좋아가 0장이면 빈 조합으로 제출한다.
- 제출은 참여자별 스냅샷이다. 선택 수정은 해당 참여자의 제출을 무효화하고 새 사진 업로드는 요청 내 모든 제출을 무효화한다. 재제출하여 조합을 갱신한다.
- 요청자의 최종 사진 확정은 기존 정책을 유지한다. 셀렉 제출과 최종 확정은 구분한다. 최종 확정 전까지 선택을 다시 살펴볼 수 있다.
- 기존 요청은 각각 동일 ID의 앨범으로 이관해 보존한다. 이후 공동 이벤트는 같은 앨범에서 요청을 추가한다. 기존 앨범 병합 기능은 이번 범위에서 제공하지 않는다.
- 닉네임은 표시 정보, 내부 사용자 ID는 소유권/멤버십 정보로 분리한다. 소셜 로그인 버튼은 MVP에서 노출하지 않는다. 추후 Google/Apple/Kakao 등의 계정 연결은 익명 ID의 데이터 보존·연결 검증을 거쳐 추가한다. Instagram의 일반 로그인 지원 가능 여부는 별도 확인 대상이다.
- Supabase 후속 마이그레이션: `202610090001_albums_and_submissions.sql`. 아직 실서버에서 실행하지 않았으며 계정 준비 후 권한/동시성 검증이 필요하다.

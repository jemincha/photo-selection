# 사진 셀렉 UIUX 다음 개선안

2026-10-09 · 실기기 MVP 테스트 이후 제안. 아래 내용은 다음 디자인 반복의 초안이며 기능 범위의 추가 확정은 아니다.

## 이번 테스트로 확인한 점

사용자가 iPhone Safari에서 셀렉 기능 전체의 정상 동작을 확인했다. 사진 권한 설정 열기의 오류는 네이티브 기능을 웹 화면에 노출한 플랫폼 분기 버그로 수정했다. 사진첩 원본 저장은 네이티브 구현이 있으나 아직 실기기 검증 전이다. 웹에서는 미지원 기능 버튼을 표시하지 않는다.

코드/기존 브라우저 화면을 기준으로 본 사용성 문제는 다음과 같다. 이는 사용자 행동 분석 결과가 아니라 화면 구조에 대한 검토다.

- 내비게이션 제목과 본문 제목이 반복되고 카드 안내가 많아 첫 화면에서 사진과 행동이 밀려난다.
- 요청 화면의 업로드/초대/분류 필터/새로고침/의견/제출/최종 확정 버튼이 비슷한 크기로 나열돼 우선순위가 흐리다.
- 공통 스크롤 레이아웃과 큰 하단 버튼 묶음이 사진 상세에도 사용돼 이미지가 한눈에 들어오지 않는다.
- 업로드에 사진 선택, 업로드 시작, 목록 이동이라는 연속 조작이 필요하고 파일 정보는 제품 언어보다 개발/테스트 정보에 가깝다.
- 친구의 셀렉 제출과 요청자의 최종 확정이 서로 다른 단계인데 상태와 문구가 충분히 분리되지 않는다.
- 로컬 모드와 역할 전환 같은 테스트 도구가 제품 흐름에 섞여 있다.

## 디자인 원칙

사진을 가장 큰 정보로 두고 각 화면에는 가장 필요한 행동 하나를 강조한다. 다른 행동은 상단 메뉴, 텍스트 링크 또는 접힌 패널로 옮긴다. 실제 분류는 기존 합의대로 버튼, 탐색은 좌우 스와이프를 유지한다. 앨범/요청/제출 구조와 원본 보관 정책은 유지한다.

## 화면별 제안

| 화면 | 제안 | 기대 효과 |
|---|---|---|
| 앨범 홈 | 사진 표지 중심의 2열 앨범 목록. 이름/날짜/진행 표시를 짧게, 새 앨범은 한 위치에 배치. 닉네임 변경은 프로필 메뉴로 이동 | 지난 이벤트를 빠르게 찾아가기 |
| 앨범 상세 | 사진 요청을 표지+요청자+진행 상태로 표시. 나/친구 소유는 카드 안에 표시하고 같은 목록 유지. 대표 행동은 내 사진 추가 | 두 역할을 별도 모드 없이 이해 |
| 내 요청 준비 | 대표 행동은 사진 추가. 참여자와 초대는 작은 상단 영역. 업로드 완료 후 바로 셀렉/공유로 이어지는 흐름 | 요청 만들기의 단계 감소 |
| 사진 업로드 | 선택 후 파일 준비/업로드를 이어서 수행하는 방안을 검토. 사진별 썸네일·진행·재시도, 전체 완료 상태. iCloud 안내는 필요 시 노출 | 반복 버튼 조작 감소, 실패 원인 이해 |
| 셀렉 상세 | 화면 높이에 맞춘 사진 영역, 상단 `7 / 20` 진행, 하단 세 분류 버튼. 선택 색과 짧은 전환으로 저장 성공 표시 후 다음 사진. 의견은 아이콘/바텀시트로 접기 | 사진이 화면 안에 들어오고 엄지로 반복 조작 |
| 제출 전 확인 | 좋아 사진을 모아 보고 `좋아 5 · 글쎄 3 · 별로 12` 요약. 수정할 사진을 누르면 상세로 이동. 대표 행동은 셀렉 제출 | 내가 보낼 조합 확인 |
| 제출 완료 | 선택 조합과 제출 완료만 먼저 표시. 대표 행동은 앨범으로. 수정은 보조 행동 | 종료 지점 명확화 |
| 요청자 최종 확정 | 제출된 참여자 조합을 비교하고 최종 사진 선택. 제목/버튼에 최종 확정을 명시, 확정 시 편집 종료 안내 | 셀렉 제출과 최종 결과 구분 |
| 확정 결과 | 최종 조합 크게 표시. 웹은 앨범으로, 네이티브는 저장 가능한 요청자에게 원본 저장. 권한 설정은 거절된 경우에만 안내 | 지원되지 않는 기능 클릭 방지 |

## 셀렉 상세의 구체적인 조정

- 공통 문서형 ScrollView 대신 사진 상세 전용 레이아웃을 검토한다. 상단 진행/이미지/하단 분류를 한 화면에 배치한다.
- Safari 주소창과 하단 홈 영역을 포함한 실제 가용 높이에 맞춰 이미지를 contain으로 표시한다. 사진 전체가 보이고 분류 버튼이 가리지 않도록 한다.
- 스와이프는 이전/다음 탐색만 수행한다. 분류 수정은 이전 사진에 돌아와 다른 분류 버튼을 누른다. 취소/되돌리기 버튼을 다시 넣지 않는다.
- 첫 진입에만 간단한 제스처 안내를 제공한다. 매 사진마다 긴 안내 문장을 반복하지 않는다.
- 빠른 연속 입력에 중복 저장/사진 건너뛰기가 없어야 한다. 실패하면 현재 사진을 유지하고 재시도를 제시한다.
- 미분류가 있으면 제출 시 해당 사진으로 안내한다. 마지막 사진이라는 이유만으로 사용자를 막다른 화면에 두지 않는다.
- 색만으로 분류를 전달하지 않는다. 글자/아이콘/선택 상태를 함께 제공하고 VoiceOver 읽기 순서를 확인한다.

## 구현 순서

1. **셀렉 상세·제출 완료를 먼저 디자인/구현**한다. 전체 사진 표시, 하단 버튼 높이, 자동 전환, 진행률, 종료 흐름을 집중 개선한다.
2. 앨범 홈·앨범 상세·요청 화면의 정보와 행동을 재배치한다. 프로필/초대/테스트 도구를 보조 영역으로 옮긴다.
3. 업로드 흐름을 간소화하고 iCloud/HEIC/재시도 경험을 다듬는다. 파일 종류나 서버 정보는 기본 화면에서 숨기고 오류 상세에만 남긴다.
4. 이 흐름이 안정되면 색·폰트·아이콘·전환 효과를 일관되게 적용한다. 새 기능/소셜 로그인/추천 조합은 별도 후속 작업이다.

기존 HTML 와이어프레임을 현재 앱보다 우선하지 않는다. 다음 반복에서는 상세/제출 전 확인/제출 완료의 모바일 화면부터 새 시안으로 리뷰한다.

## 검증 시나리오

- iPhone 12 세로 화면에서 Safari 주소창을 펼치고 접어도 사진 전체와 분류 버튼을 볼 수 있다.
- 사진 10장을 한 손으로 연속 분류하고, 중간 사진으로 스와이프 복귀해 수정한 뒤 제출한다.
- 설명 없이 셀렉 제출과 요청자의 최종 확정을 구분할 수 있다.
- 같은 앨범에서 내 요청과 친구 요청을 찾고 각자의 작업을 이어갈 수 있다.
- 업로드 실패 항목만 재시도하고 정상 완료된 사진은 중복 추가하지 않는다.
- 미지원 웹 저장/권한 설정 버튼이 없으며 에러가 페이지 전체를 덮지 않는다.

처음 사용할 때 헤매는 지점, 불필요한 이동 횟수, 사진 잘림, 버튼 오탭을 관찰한다. 실제 관찰 전 사용성이 개선됐다고 수치로 단정하지 않는다.

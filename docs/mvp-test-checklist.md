# MVP 피드백 체크리스트

## 로컬 흐름

- 이름 저장·요청 생성·제목 유효성 확인.
- 실제 사진 3~5장 선택 후 업로드, 앱 재실행 후 사진 유지.
- 사진 좌우 탐색에서 첫·마지막 경계, 세로 스크롤과의 충돌 확인.
- 별로·글쎄·좋아 변경, 미분류 복귀, 되돌리기. 사진 넘기기는 반응을 바꾸지 않아야 함.
- 사진별 의견과 전체 의견 구분.
- 테스트 친구 반응 → 요청자 복귀 → 최종 선택. 친구에게 확정·원본 저장 권한이 없어야 함.
- 확정 후 반응·의견은 읽기 전용, 사진 탐색은 가능.

## iPhone 12

- JPEG·HEIC·iCloud 사진의 회전·포맷·해상도·파일 크기·선택 시 변환 여부 기록.
- 업로드 원본과 다운로드 결과의 파일 동일성 확인. 썸네일이 저장되지 않아야 함.
- 사진 추가 권한 거부·재허용, 일부 저장 실패·재시도, 저장 중 앱 종료.
- 저장 완료 사진이 재시도 시 중복 저장되지 않는지 확인. OS 저장 완료와 기록 사이 앱 종료 시 중복 가능성은 별도 점검.
- 키보드와 하단 분류 버튼이 겹치지 않는지, 사진 높이·제스처·뒤로 가기 충돌 확인.

## 연결 모드 — Supabase 설정 후

- 두 실제 기기에서 초대 열기 → 이름 → 참여 → 사진 조회 → 분류·의견 반영.
- 각자가 요청을 만들고 상대 요청에도 참여해 홈에서 역할이 자동 변경되는지 확인.
- 제3자 인증 세션에서 다른 요청 ID·원본 Storage URL 접근 차단.
- 친구의 원본 접근·확정·사진 업로드 차단.
- 확정과 반응 변경이 동시에 발생해도 서버가 확정 이후 변경을 막는지 확인.
- 업로드 부분 실패에 생성된 고아 파일이 정리되는지 확인.
- 익명 세션 삭제·Apple 로그인 전환 시 복구 정책 검토.

## 현재 실행하지 못한 검증

Supabase 프로젝트·Apple Developer 계정이 없어 실제 SQL 적용, 두 기기 통신, Apple 로그인, EAS 빌드·서명, TestFlight 제출은 수행하지 않았다. iPhone 실기기 저장도 사용자의 테스트가 필요하다.

## 이번 세션에서 확인한 브라우저 흐름

실제 Expo 웹 앱에서 이름 저장, 요청 생성, 기본 제공 PNG 테스트 이미지 두 장 선택·업로드, 테스트 친구 전환, 글쎄→좋아→되돌리기, 사진 의견·전체 의견 저장, 사진 탐색, 그리드 분류 반영, 요청자 최종 확정, 확정 후 입력 차단과 사진 탐색 유지까지 확인했다. 테스트 데이터는 로컬 브라우저에만 있다. 결과 스크린샷은 `docs/screenshots/mvp-result.png`에 보관했다.

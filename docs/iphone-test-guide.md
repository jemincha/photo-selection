# iPhone 12 테스트 가이드

현재는 Apple Developer 계정 없이 iPhone Safari에서 웹 MVP를 테스트한다. 네이티브 설치/사진첩 원본 저장 테스트는 별도 단계다.

## 지금 접속

1. Windows 노트북과 iPhone을 같은 일반 Wi-Fi에 연결한다. 게스트 Wi-Fi의 기기 간 차단은 피한다.
2. 노트북을 켜두고 서버를 실행한 상태로 유지한다.
3. iPhone Safari 주소창에 `http://192.168.11.60:8082`를 입력한다. `localhost`는 iPhone 자신을 가리키므로 사용하지 않는다.
4. 닉네임 → 새 앨범 → 내 요청 추가 → 사진 선택을 진행한다. 처음에는 작은 JPEG 또는 PNG/스크린샷 2~3장을 사용한다.
5. 업로드 시작 → 사진 목록·초대로 이동 → 이 요청을 테스트 친구로 열기 → 사진 셀렉 시작.
6. 별로/글쎄/좋아 선택 시 다음 사진으로 이동하는지 확인한다. 오른쪽 스와이프는 이전 사진, 왼쪽은 다음 사진이다.
7. 모든 사진을 분류하면 마지막 사진 또는 목록의 셀렉 제출 버튼으로 제출한다. 텍스트 의견 없이도 제출 가능하며 좋아 조합이 표시된다.
8. 앨범으로 복귀해 같은 앨범에 친구의 요청을 추가한다. 나로 돌아오면 한 앨범에서 내 요청과 친구 요청을 함께 볼 수 있다.
9. Safari 새로고침 후 앨범/셀렉이 남아 있는지 확인한다.

테스트 데이터는 iPhone의 해당 Safari 사이트 저장소에 보관된다. PC 브라우저와 데이터는 공유되지 않는다. 주소/포트 변경이나 Safari 사이트 데이터 삭제 시 별도의 저장 공간으로 취급된다. 사진첩 저장과 실제 사용자 간 공유는 이 웹/로컬 테스트에서 제공하지 않는다.

## 연결되지 않을 때

- 먼저 PC 브라우저에서 `http://192.168.11.60:8082`가 열리는지 확인한다.
- PC의 현재 Wi-Fi 프로필은 Public이다. 본인이 신뢰하는 집 Wi-Fi라면 Windows 설정 → 네트워크 및 인터넷 → Wi-Fi → 현재 네트워크 속성에서 Private으로 설정할 수 있다.
- Windows 보안 → 방화벽 및 네트워크 보호 → 방화벽을 통해 앱 허용에서 Node.js JavaScript Runtime의 Private 네트워크 허용을 확인한다. 회사/공용 네트워크의 보안 정책을 임의로 바꾸지 않는다.
- 방화벽을 끄지 않는다. VPN/게스트 Wi-Fi의 기기 간 차단 여부를 확인한다.
- Wi-Fi 주소가 바뀌었다면 PowerShell의 `ipconfig`에서 Wi-Fi IPv4 주소를 확인하고 새 주소의 `:8082`로 접속한다.
- 오류가 계속되면 Safari 오류 문구와 PC에서 해당 주소가 열리는지 알려준다.

## 네이티브 iOS 단계

이 프로젝트는 SDK 57이다. Expo 공식 문서에 따르면 App Store Expo Go는 SDK 54까지이며 이후 SDK의 실제 iPhone 설치는 별도 배포가 필요하다. 따라서 App Store Expo Go를 설치하고 QR만 읽는 방법을 현재 안내하지 않는다.

Apple Developer Program 가입과 Expo 계정/EAS 설정 후 SDK 57용 Expo Go 또는 앱 development build를 배포해 테스트한다. Windows에서도 EAS 클라우드 빌드는 가능하다. 그 단계에서 터치/권한/원본 사진 저장/딥링크를 별도로 검증한다.

출처: https://docs.expo.dev/troubleshooting/expo-go-version-mismatch/


## iCloud 사진 업로드 오류 확인

업로드 시작 후 실패하면 각 사진 아래의 `[파일 읽기]`, `[미리보기 생성]`, `[기기 저장]` 및 실제 오류 문구를 확인한다. 파일 형식과 MB 크기도 표시된다.

- iCloud 최적화는 원본을 훼손하는 압축이 아니라 기기에 작은 버전을 두고 원본을 iCloud에 유지하는 방식이다.
- 사진 앱에서 해당 사진을 열고 다운로드를 기다린 뒤 다시 선택한다. 전체 보관함을 다운로드하도록 설정을 바꿀 필요는 없다.
- 미리보기 생성 단계의 HEIC/HEIF 실패라면 해당 파일의 Safari 디코딩 문제일 수 있다. JPEG/PNG 파일과 비교 테스트한다. 앱은 원본을 자동으로 JPEG로 바꿔 저장하지 않는다.
- 기기 저장 실패에는 Safari 저장 공간을 확인한다. 원본은 IndexedDB로 옮겼으므로 기존 localStorage 문자열 용량 한계를 피한다. 브라우저 사이트 데이터 삭제는 기존 테스트 사진/앨범을 잃게 하므로 오류 해결을 위해 바로 삭제하지 않는다.

변경 후 Safari 새로고침 → 같은 사진 한 장 재선택 → 업로드 → 실패 단계/오류 문구 확인 순서로 재검증한다. 오류가 다시 발생하면 문구를 그대로 공유한다. 실제 iCloud 사진 다운로드/HEIC 동작은 사용자의 실기기 검증이 필요하다.

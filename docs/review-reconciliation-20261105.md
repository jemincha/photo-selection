# 심사·UX 리뷰 대조와 다음 우선순위

2026-11-05 · 개발 검토용. README와 UIUX 문서에 대한 외부 리뷰를 현재 문서와 관련 소스에 대조했다. 화면 실행·빌드·실기기·실서버 검증 결과가 아니며 심사 결과를 예측하지 않는다. 출시 증빙 상태는 `release/review-evidence.json`을 유지한다.

## 현재 상태와 리뷰의 차이

| 지적 | 현재 확인한 근거 | 남은 일 |
|---|---|---|
| 계정 삭제·보관 정책 없음 | `mobile/src/app/account-delete.tsx`, `account-deletion.ts`, `app/privacy.tsx`에 삭제 흐름과 확정 후 서버 30일 보관 안내 존재 | 실제 Auth·Storage 삭제, 실패 후 접근 차단·재처리, 백업 정책 검증 |
| 신고·차단·초대 폐기 없음 | `request-actions.tsx`에 사진/셀렉/참여자 신고, 차단, 초대 회전·중지, 셀렉과 서버 사진 삭제 존재 | 서버 권한·기존 링크 차단·운영 대응 검증. 개별 사진 삭제와 앨범 나가기를 셀렉 전체 삭제로 대체했다고 보지 않음 |

| 원하는 사진으로 돌아가기 어려움 | `photo.tsx`의 이전/다음·분류별 보기와 `selection-sheet.tsx`, `photo-groups.tsx`의 그룹 사진 이동 존재 | 100장에서도 찾기·수정이 쉬운지 확인. 필름스트립 추가는 관찰 후 결정 |
| 글쎄·별로 정보 소실 | 최신 피드백 기록에 친구별 분류 보기와 확정 후 전체 후보·현재 반응 조회 반영 | 사진별 집계와 모두 좋아 필터는 별도 개선 후보. 현재 반응과 과거 수정 이력을 구분 |
| 상세 확대·해상도 부족 | `photo.tsx`는 `photo.thumbnail`을 contain으로 표시하고 탐색 PanResponder 사용. 핀치/더블탭 확대 경로 없음. 웹 썸네일 기본 상한은 `web-photo.ts`의 720px | 실제 업로드 결과 해상도 확인, 상세용 이미지·확대·제한된 프리로드 구현 및 측정 |
| 초대 첫 경험 | `app/invite/[token].tsx`는 닉네임 입력·동의 후 참여 | 신규 설치/기존 사용자 각각 링크부터 첫 사진까지 측정. 기본 닉네임은 중복·변경·동의 흐름까지 검토 |
| 업로드 복원 없음 | 기존 웹 복원 문서와 업로드 큐가 존재 | 웹 복원을 iOS 백그라운드 업로드 보장으로 해석하지 않음. 셀룰러·중단·강제종료·재시도 실기기 검증 |

README의 과거 MVP 기록만 읽으면 이미 구현된 안전 기능을 미구현으로 판단할 수 있다. 최신 구현 안내를 먼저 읽도록 링크를 추가했다. 구현 존재가 출시 검증 완료를 뜻하지는 않는다.

## 심사 요구와 제품 개선의 구분

Apple 공식 [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/)를 2026-11-05 확인했다.

- 5.1.1(v)는 계정 생성 지원 시 앱 내 삭제를 요구한다. 현재 삭제 UI 존재에 더해 실제 삭제 완료와 실패 복구를 증명해야 한다.
- 1.2는 부적절한 콘텐츠 필터링, 신고와 적시 대응, 사용자 차단, 공개 연락처를 요구한다. 앨범 나가기·초대 폐기는 이 공유 구조의 보호 수단으로 평가하며 조항의 명시 항목과 구별한다.
- 4.8은 제3자 로그인으로 주 계정을 설정·인증할 때 조건에 맞는 동등한 로그인 옵션을 요구하며 예외가 있다. 현재 소셜 로그인 미제공만으로 Apple 로그인 의무를 단정하지 않는다. 익명 계정 복구·연결은 별도 데이터 연속성 과제다.
- 2.1의 완성도·심사 접근과 2.2의 베타 배포 요구를 함께 확인한다. 개발용 역할 전환 도구는 정식 빌드에서 접근 불가임을 확인한다. 심사용 계정·접근 정보는 정상 권한 흐름으로 요청자와 참여자 행동을 재현할 수 있어야 한다.
- 푸시·햅틱·다크 모드·참여 인원 확대는 제품 개선 후보다. 이를 모두 심사 필수 기능으로 묶지 않는다.

### 권한과 EXIF에서 먼저 결정할 점

`original-album-save.tsx`는 기존 자산을 찾아 연결하기 위해 읽기를 포함한 Photos 권한을 요청한다. 따라서 현재 기능에 ‘추가 전용만 요청’ 정책을 그대로 적용할 수 없다. 기존 사진 연결에 필요한 읽기 권한과 저장 전용 폴백을 구분하고 거절해도 나머지 앱을 쓸 수 있어야 한다.

원본 바이트·체크섬 보존과 원본 GPS 제거는 동시에 같은 파일에 적용할 수 없다. 현재 개인정보 화면은 원본에 위치정보가 포함될 수 있음을 알린다. 친구에게 전달하는 미리보기의 GPS 제거 여부를 샘플 추출로 확인하고 원본은 요청자만 접근하는지 검증한다. 원본까지 제거하려면 파일 변형·체크섬·기존 자산 매칭·저장 동작·정책을 함께 변경해야 하므로 이번 문서에서 제거 완료를 주장하지 않는다.

실행 결과는 기존 테스트 체크리스트와 출시 증빙 파일에 기록한다. 문서 검토만으로 pending 항목을 통과로 변경하지 않는다.

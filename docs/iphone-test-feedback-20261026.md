# 설렉 v2 · iPhone 테스트 피드백

2026-10-26 · 사용자 직접 테스트 · Expo SDK 58 기준 현 버전 보존

## 기록의 범위

사용자는 기본 테스트 기능은 정상 수행된다고 평가했으나, 성능·화면 복잡도·역할 구분·다량 사진 셀렉에서 개선이 필요하다고 보고했다. 아래는 **피드백 기록이며 다음 업데이트의 확정 사양이 아니다.** 이번에는 기능을 수정하지 않고 현 버전을 커밋한다. 사용자가 Claude에서도 테스트하고 교차 피드백한 뒤 다음 업데이트안을 전달할 예정이다. 이 기록을 근거로 다른 에이전트에 메시지를 보내거나 구현을 시작하지 않는다.

## 사진 저장 방식 · 현재 코드에서 확인한 사실

### Supabase 미연결 로컬 모드

사진을 준비할 때 원본 바이트를 읽어 앱의 문서 폴더에 사본을 저장한다. 최종 저장 시 그 **앱 내부 사본**의 크기·SHA-256을 검증하고 `MediaLibrary.createAssetAsync`로 사진 앱에 새 자산을 만든 뒤 설렉 전용 앨범에 추가한다.

즉, 기존 사진 앱 자산 ID를 그대로 전용 앨범에 연결하는 방식은 아니다. 기존 원본이 사진 앱에 있어도 저장본이 추가될 수 있다. 이 경로에는 서버 다운로드가 없다.

### Supabase 연결 모드

Storage 원본의 임시 다운로드 URL을 발급받아 앱 캐시로 **서버 원본을 다시 내려받는다.** 크기·SHA-256을 검증한 뒤 사진 앱에 새 자산을 만들고 전용 앨범에 추가한다. 다운로드한 임시 캐시는 처리 후 정리한다. 현재 구현은 사진별로 순차 저장한다.

완료한 자산·앨범 기록을 보존해 재시도 시 완료 사진을 건너뛰고, 앨범 추가만 실패하면 만들어 둔 자산을 재사용한다. 이번 사용자 테스트가 어느 모드였는지, 실제 장수·원본 용량·소요 시간은 메시지만으로 확정하지 않는다.

확인 위치: [원본 앨범 저장](../mobile/src/original-album-save.tsx), [사진 준비·원본 URL](../mobile/src/repository.ts), [원본 검증](../mobile/src/verify-original.ts), [순차 저장·재시도](../mobile/src/save-album.ts). 전체 파일 읽기·검증·사진 앱 복사·서버 다운로드는 측정할 후보이며, 아직 특정 구간을 병목 원인으로 단정하지 않는다.

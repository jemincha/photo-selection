# 사진을 열면 바로 고르기 · 철수와 영희

2026-11-05 · 개발·재테스트 안내용

## 이벤트의 핵심 동작

이벤트에서 친구의 사진을 누르면 같은 화면에 투표 버튼을 표시한다. “이 사진 골라보기” 중간 단계를 제거했다. 투표를 저장한 뒤 다음 친구 사진으로 이동하며 자기 사진은 투표 대상으로 삼지 않는다. 사진 순서를 열 때 고정해 투표 집계가 바뀌어도 탐색 순서가 흔들리지 않게 했다. 분류를 모두 마치면 “고르기 끝내기”로 기존 조합 확인·제출에 진입한다. 제출과 최종 확정은 여전히 별개다.

## 스와이프와 확대

iPhone은 JavaScript 터치 계산 대신 iOS ScrollView의 기본 핀치 확대를 사용한다. 1~8배 연속 확대, 확대 중 사진 이동, 원래 크기로 돌아오기 버튼을 제공한다. 원래 크기의 한 손가락 스와이프로 사진을 이동하고, 핀치·확대 이동은 사진 넘김으로 처리하지 않는다. 네이티브 스크롤이 터치를 취소하는 경우에도 드래그 종료를 통해 탐색하며 한 제스처가 두 장을 넘기지 않도록 막았다. 이전·다음 버튼도 제공한다.

웹·Android의 기존 제스처는 터치 캡처와 이동 응답을 명시하고 부모 뷰가 제스처를 중간에 가져가지 않도록 보강했다. 실제 기기의 실패 상황을 직접 재현한 검증은 아직 아니다.

## 동등한 로컬 사용자

기존 로컬 ID는 유지하며 기본 이름을 철수·영희로 바꾼다. 기존 ‘제민’, ‘테스트 친구’ 이름은 데이터 초기화 없이 치환한다. 두 사용자 모두 사진 업로드, 상대 사진 투표, 자신의 최종 확정을 수행한다. 설정과 이벤트의 “사용자 전환”을 사용하며 마지막 사용자도 기억한다. 이벤트에서 전환하면 초대 참여를 거쳐 상대 사용자로 확인한다. 설정에서 전환하는 것은 초대 참여를 대신하지 않는다.

실서버 계정을 다른 사람으로 전환하는 기능은 추가하지 않았다.

## iCloud 대기

현재 SDK 58 사진 선택은 Current representation·quality 1·편집 없음으로 원본 복사 경로를 이미 사용한다. 품질을 낮춰도 원본 다운로드가 없어지는 것은 아니므로 원본 보관 정책을 유지했다. 사진 선택기가 반환하기 전의 iCloud 다운로드 진행률은 이 API에서 제공하지 않아 퍼센트를 만들지 않는다.

가져오기 안내를 추가하고, 선택 완료 후 모든 사진의 임시 복사를 먼저 끝내던 처리를 한 장씩 복사→검증→미리보기→보관·업로드하는 순서로 바꿨다. 한 장의 복사가 실패해도 다음 사진을 처리한다. 네트워크에서 원본을 받는 시간 자체는 남는다. 선택 창에서 계속 오래 걸리면 원본을 기기에 미리 내려받거나 작은 묶음으로 선택해 테스트한다.

미리보기로 먼저 셀렉을 시작하고 원본은 나중에 받는 구조는 별도 작업이다. 현재 변경에서 원본 보관을 생략하거나 저화질 파일로 대체하지 않았다.

공식 참고: [Expo SDK 58 ImagePicker](https://docs.expo.dev/versions/v58.0.0/sdk/imagepicker/), [Apple iCloud 네트워크 다운로드](https://developer.apple.com/documentation/photos/phimagerequestoptions/isnetworkaccessallowed), [React Native ScrollView](https://reactnative.dev/docs/scrollview).

## 검증

모바일 자동 테스트 63개, TypeScript·lint, 웹 production export와 iOS Hermes 번들 export 통과. 실제 컴포넌트의 네이티브 확대 설정과 터치·스크롤 이벤트, 직접 투표 노출과 자기 사진 투표 숨김, 철수·영희의 양방향 업로드·투표·확정, 한 장씩 준비 및 복사 실패 후 다음 장 진행을 검사한다. 테스트의 네이티브 뷰·사진 저장 경계는 모의 객체다.

iPhone Expo Go에서 다시 확인할 항목: 이벤트에서 사진 열자마자 투표, 좌우 탐색, 두 손가락 확대 후 드래그·원래 크기 복귀, 사용자 전환 후 양쪽 업로드와 상대 투표, 실제 iCloud 원본 대기 시간. 다운로드 속도 개선 수치는 측정하지 않았다.
